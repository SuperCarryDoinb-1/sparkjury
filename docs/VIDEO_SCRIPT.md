# 演示视频脚本（3 分 30 秒）

结构按备赛指南：Problem → Magic → Explain。画面全部来自真实运行，不做 PPT 动画。录屏 1080p，Cockpit 用侧栏「切换深色 / 浅色」切到深色主题，终端字号调大。

## 0:00 - 0:30 Problem

画面：一张真实的 trace JSON 滚屏，几百行工具调用；切到一个产品经理翻记录的表格。

旁白：
> 你的 Agent 上线了，trace 每天几千条，谁在看？LangChain 去年底调研了 1340 个团队，89% 接了可观测，30% 完全不做评测。我们自己的公司，11 个场景的 badcase 靠产品经理一条条翻。能自动归因的产品全在云上，而 trace 里是用户的对话。

字幕：有 trace，没评测。本地能用的，没有。

## 0:30 - 0:45 一句话

画面：DGX Spark 实机特写，切到 Cockpit 首页。

旁白：
> SparkJury：一台 DGX Spark，顶一个评测组。

## 0:45 - 2:15 Magic（Wow 段，60 到 90 秒）

画面：Cockpit 首页（九页工作台，左侧导航）。点「新建评测任务」，裁判选「真实裁判（配置文件）」，输入选内置样本或已上传的 τ²-bench 数据，开始后页面自动切到「评测任务」页跟事件流。

1. **0:45** 「评测任务」页：七个阶段依次亮起，事件流滚动；切回首页时六步评测流程同步点亮。旁白："先排除不是 Agent 的错：这条工具后端 503 三次，直接标掉，不进评分。"（镜头停在 PRECHECK 的 degraded/env 行）
2. **1:00** SCORE 阶段：右侧 DGX Spark 卡里四个本地模型端点绿灯，GPU 显存条涨到 90 GB。旁白："三个裁判来自三个家族：Qwen 和 Nemotron 常驻在这台机器的 128G 统一内存里，第三家 StepFun 的 step-3.7-flash 在云端。四个维度：结果、工具、效率、安全。"（9 月 29 日起 StepFun key 已配好、三家族齐活；若录制当天云端连不上，改讲"系统降级成本地双裁判加占位裁判，并在看板铃铛与卡片上如实标注——降级不是藏起来，是标出来"。）
3. **1:20** 事件流里出现 `scored ... disagreement`。旁白："这一条，三位裁判意见不一致。"点这一行，跳到「模型裁判」页的「裁判理由并排」：四个维度 x 三位裁判的分数与理由并排，分歧那一行左侧红色竖线加「三票分歧」标记，右侧「最终裁决」列显示仲裁来源（云端 Jev 仲裁或本地仲裁）与「已降级」标记，对话记录里证据步骤高亮。页面上方的「裁判面板」表与「各维度得分分布」柱图顺手带一眼：三家族的模型名、票数、错票、单票耗时。（不再切终端；终端版 `sparkjury verdicts <id>` 只作备选。）
4. **1:30** ARBITRATE：事件流出现 Jev 仲裁。旁白："分歧送云端 Jev，一个不生成文字、只回分数的决策模型，每百万 token 4 美分。"「评测任务」页 DGX 卡里「云端 Jev 裁决」计数跳动；「评测结果」页的「裁决来源分布」环图给出合议一致与 Jev 仲裁的占比。（备选：断网演示，黄色 degraded 行，"没网也不停，本地仲裁，标记降级"。）
5. **1:50** CLUSTER + REPORT：切「评测结果」页——可用率大数、黑卡「先修什么 / 怎么改」、分场景表；再切「证据卡片」页。旁白："几十条 badcase 聚成三类。第一类：没验证身份就执行写操作，严重度最高。建议：把写操作挡在工具层的身份校验之后。"左下填决策人，点「确认优先修复」，卡片标「已确认」，决策写进账本。
6. **2:05** 切到终端改 prompt 一行（加入"任何写操作前必须完成身份验证并取得明确 yes"），重跑；切回 Cockpit「回归对比」页：改前选上一次任务，点「对比」。画面：徽标「改善」，pass^3 从 X% 到 Y%，「已修复的任务」列表，「已退化的任务」为空，簇的 badcase 数下降。（「失败聚类」页在 1:50 之后顺手点一下「展开 N 条成员」，展开成员明细。）旁白："改一行，重跑，pass^3 涨了，没有任务变坏。这就是一轮。"

字幕关键数字：trace 数、badcase 数、簇数、pass^3 前后、耗时。

## 2:15 - 3:10 Explain

画面：架构图（README 里那张），逐层高亮。

旁白：
> 为什么在 DGX 上。三个不同家族的裁判要同时在线，同一家互相评没有信息量，论文测过九个前沿 judge 只有两票是独立的。几百条 trace 乘四个维度乘三个裁判是几千次打分，每次迭代都要重跑，本地跑只花电费。trace 不出企业，只有三票分歧的摘要送云端，而且可以关。
>
> 底座是 NVIDIA NeMo Agent Toolkit：它提供轨迹评估和 profiler，SparkJury 注册成它的评估器，补上跨模型仲裁和归因优先级这一层。六个能力打包成 Agent Skills，符合 NVIDIA 注册表格式。
>
> 我们不承诺根因。自动定位出错步骤，前沿模型也只有一两成准确率。我们给聚类、优先级和证据，人来拍板。

画面：卡片底部的免责声明特写。
